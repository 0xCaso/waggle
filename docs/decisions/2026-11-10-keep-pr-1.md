# Do I redo the fork and the PR, or keep PR #1?

Decided: 2026-11-10 · Case: c_c0de85fe-f7e7-4e6b-8dac-714249d5c389 (follows c_abba85ea-e434-41e5-a5d5-25eba654c522)

## Question and choice
The operator asked to delete the fork, fork again and open a new PR, so the old commit cannot be found, all files can be attached, and all text is in English. A new fork and PR do neither of the first two.
Chosen: "Keep PR #1. I translate all Italian text in the PR to English and amend. I write the text for a GitHub private-data removal request for commit a66c2e1. You send it."

## Why
- GitHub shares git data across the fork network: commits of a deleted fork stay reachable from the upstream repo, and PR #1 in waggle-so/waggle still points to the old commit.
- `gh --attach` needs write access to waggle-so/waggle; a new fork has the same limit.
- Only GitHub can delete the old commit and PR #1's reference to it.

## Constraints
- All text in the PR files is in English; the operator's words are translated.
- PR #1 stays the one PR for this work.
- No new fork, no fork deletion.

## Ruled out
- Ask the owner for write access: not picked.
- Redo fork and PR: the old commit stays reachable, still no attachments, and deleting the fork cannot be undone.
